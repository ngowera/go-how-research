# Publish on www.afrisoft.online

Target repository: https://github.com/parcelexpert2-png/go-how-research

The app supports links such as `https://www.afrisoft.online/kondwani001`.
Each published questionnaire has a unique, fixed name enforced by Supabase.
Multiple researchers can publish separate questionnaires without sharing access
to each other's participants or responses. A link is public: anyone who has it
can answer, but cannot read responses.

1. Push this project to the chosen GitHub repository's `main` branch. Do not
   commit `.env`, database files, interview recordings, or research exports.
2. In repository Settings → Secrets and variables → Actions, create the variable
   `SUPABASE_URL` with `https://apnpooljfbacejhsktwj.supabase.co` and secret
   `SUPABASE_ANON_KEY` with the project's publishable/anon client key. Never put
   a service-role key or Gemini key here: web client values are publicly visible.
3. In Settings → Pages select **GitHub Actions**, and set the custom domain to
   `www.afrisoft.online`. The included workflow builds and deploys the Flutter app.
4. In Namecheap DNS, point the `www` CNAME to `parcelexpert2-png.github.io`.
   Check existing DNS records before replacing them. Once GitHub validates the
   domain, enable HTTPS. Verify domain ownership in GitHub's Pages settings.
5. Add `https://www.afrisoft.online` to the Supabase Auth site/redirect configuration
   if this is the primary sign-in site. Retain any other required app redirects.
6. Open the site, sign in, and choose Questionnaires → **Collect / Share**. Use
   **Answer on this device** for local/offline collection. To accept browser
   responses, set the unique link name, study information, participant details,
   and expiry, then publish and copy the link.
7. Test the link in a signed-out browser with synthetic answers. Verify the
   confirmation receipt, then check Participants and the dataset in the owner
   account. Automatic sync fetches responses every 10 seconds while the app is
   open and online. **Close link** stops further responses.

GitHub Pages uses the built `404.html` fallback to load Flutter's clean URLs.
The initial deep-link HTTP response can be 404 while the questionnaire renders
normally. The fallback is generated by `tool/prepare_pages.py` during deployment.

The public server is `supabase/functions/questionnaire-link`. The server checks
ownership for publishing, validates answers, respects conditional questions,
checks expiry, and inserts participant/response/receipt records in one transaction.
Repeated sends of the same submission ID return the original receipt. This avoids
duplicates from network retries, but does not enforce one response per person.
